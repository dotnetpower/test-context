# Test Context (`tctx`) incremental test & lint execution (Python, Rust, Frontend)

TCTX (`test-context`) maintains an in-memory polyglot (**Python + Rust + Frontend TS/JS/JSX/TSX/Vue/Svelte/CSS/SCSS**) AST reverse dependency graph, computes live SHA-256 Merkle dependency hashes (`dep_hash`) for every test file, pre-checks modified files with **Ruff** and **ESLint**, and speculatively runs affected tests (`pytest`, `cargo test`, `vitest`, `jest`, `node --test`) in the background when files are saved.

- In a VS Code foreground session, MUST use `#tctxNativeRun` (`test-context-native_testRun`) FIRST before MCP or shell `pytest` / `cargo test` / `vitest` / `jest` / `node --test` in a registered workspace.
  - Always pass the explicit absolute `root` parameter when the workspace or worktree path is known (especially in Windows/WSL Agent Sessions, subagents, and multi-root setups).
  - You can pass workspace-relative or absolute paths to modified source files (`.py`, `.rs`, `.ts`, `.tsx`, `.js`, `.jsx`, `.vue`, `.svelte`, `.css`, `.scss`, `.go`), test file paths, node IDs (`path::test_name`), or test directories in `targets`. If you pass a modified source or stylesheet file (or omit `targets` in a large workspace with uncommitted `git diff` edits), TCTX automatically expands it to all transitively affected test files across Python, Rust (including PyO3/maturin bridges), and Frontend (including barrel `index.ts` symbol tree-shaking, `@/` & `#subpath` aliases, `import.meta.glob`, Web Workers, and Storybook `*.stories.tsx` play tests).
  - When all targeted test files have already passed against their current live `dep_hash` (in the background worker or a prior run), `#tctxNativeRun` returns the cached green result in **< 5ms** (`mode=instant_cache_hit`, `executed_files=0`) without spawning a test runner.
  - When some test files are uncached or modified, `#tctxNativeRun` reuses cached passes for unchanged files, joins any in-flight background execution, prioritizes previously failed tests first, and runs `pytest` / `cargo test --lib` / `vitest` / `jest` / `node --test` **only on the uncached delta** (`mode=hybrid_delta`).
  - TCTX runs tests in the daemon's environment, not the shell's. A result with `skipped > 0` is never cached and is not verification: when the `SKIPPED` lines name a missing variable or service (for example a database URL), run those tests directly with the project's own wrapper instead of reporting them as passed. A replayed cached failure can be re-executed with `rerun_failed` or `no_cache`.
- Use `#tctxNativeAffected` (`test-context-native_testAffected`) to inspect which Python, Rust, or Frontend test files are affected by specific source files or current `git diff` changes, along with their dependency chains, live background cache states (`cached_passed`, `cached_failed`, `running_in_background`, `queued_in_background`, `uncached`), and pre-checked **Ruff / ESLint diagnostics** (`ruff_diagnostics`).
  - Whenever `#tctxNativeAffected` or `#tctxNativeRun` reports `[ruff]` or `ruff_errors`, resolve those Ruff or ESLint lint/syntax errors immediately (either by passing `ruff_fix: true` to `#tctxNativeRun` for `[fixable]` rules, or by editing the reported `file:row:col` directly) before concluding your work.
- Use `#tctxNativeGraph` (`test-context-native_testGraph`) to inspect direct imports, reverse importers, transitive dependencies, `conftest.py` / `tests/common` / `setupTests.ts` chains, referenced env vars, and test symbols for any Python, Rust, or Frontend file.
- When delegating to subagents (`task`, `general-purpose`, `explore`, `code-review`, `rubber-duck`, `security-review`), ALWAYS include the target absolute `root` in the prompt and explicitly instruct the subagent to use `#tctxNativeRun` / `#tctxNativeAffected` / `#tctxNativeGraph` or `test-context-test_*` MCP tools first (and to discover deferred tools with exact names via `tool_search` if not immediately visible).
- If Test Context tools are deferred or not yet visible in the active tool list, discover them first with `tool_search` using exact names for both Native and MCP surfaces: query `"tctxNativeRun tctxNativeAffected tctxNativeGraph tctxNativeStatus tctxNativeSync tctxNativeInvalidate tctxNativeWorkspaces test-context-test_run test-context-test_affected test-context-test_graph test-context-test_status test-context-test_sync test-context-test_invalidate test-context-test_workspaces"` (when no UI client is connected, `tool_search` only matches exact tool names, so including the `test-context-test_*` names loads the MCP tools in one call).
- Do not choose MCP when the matching Native tool is callable.
- If a native `#tctxNative*` call fails with `"No matching client connected"` or `"Client ... disconnected"`, immediately switch to `test-context-test_*` MCP tools (`test-context-test_run` / `test_run`, `test-context-test_affected` / `test_affected`, `test-context-test_graph` / `test_graph`, `test-context-test_status` / `test_status`, `test-context-test_sync` / `test_sync`, `test-context-test_invalidate` / `test_invalidate`, `test-context-test_workspaces` / `test_workspaces`) or the `tctx --root /path/to/repo run` / `affected` / `graph` / `pytest` / `cargo-test` / `vitest` / `jest` / `ruff` CLI instead of falling back to raw shell runners. All surfaces talk to the same shared `tctx daemon`.
